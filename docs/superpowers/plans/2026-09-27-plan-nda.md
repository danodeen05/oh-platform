# Plan NDA Implementation Plan

Spec: docs/superpowers/specs/2026-09-27-plan-nda-design.md


**Goal:** Ship the NDA gate end to end on dev, verify, merge to main, deploy, verify prod, email the owner.
**Architecture:** API module `packages/api/src/plan/nda*.js` (+ `pii.js`), registered from `registerPlanRoutes`; web `lib/plan/nda/*`, `app/[locale]/plan/nda`, `app/api/plan/nda/*`; admin `apps/admin/app/plan-access/*`.
**Tech:** Fastify 4, Prisma, node:test; Next 16, @react-pdf/renderer 4, vitest; Twilio `sendSMS`; Graph `sendGraphMail`.

## Global constraints
- No em dashes in any user-facing copy; Chappy copy has no exclamation points or emojis.
- Plan `<button>` needs a bg class; inputs need `focus:bg-*`/`focus:text-*` and 16px text on phones.
- Stage by explicit path; never `git add -A`; exclude `fromDano/`, tsbuildinfo.
- Keep `PLAN_VISIT_SUMMARIES=off` on dev.
- Prod DB migration applied by psql (additive), per [[plan-access-infra]].

## Review focus (tests added in owning tasks)
1. Reload or back mid-flow resumes the right step with details kept (Task 4 state tests).
2. Double submit / two tabs: exactly one SIGNED transition and one delivery (Task 5).
3. Owner turns `ndaRequired` off while pending → immediate access (Task 3).
4. Revoked code while pending → gate, not NDA (Task 3).
5. Email failure → sign still succeeds, text says "on its way", deliveryError recorded (Task 5).
6. Phone formats `(801) 555-1234`, `+44 20 ...` normalize; junk rejected (Task 2).
